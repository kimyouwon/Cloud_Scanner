# Kubernetes 보안 스캐너 연구 방법

## 1. 룰 구조화/코드

### 체크 모듈 기반 구조화
- **추상 기본 클래스(ABC) 패턴**: `Check` 추상 클래스를 정의하여 모든 보안 체크의 공통 인터페이스 제공
  - 필수 속성: `id`, `name`, `category`, `severity`, `description`, `points`
  - 추상 메서드: `run()` - 각 체크의 핵심 로직 구현
  
- **모듈화된 체크 구조**: 각 보안 항목을 독립적인 Python 모듈로 분리
  - Pod 보안: `M_PSA_001_privileged.py`, `M_PSA_002_namespace_isolation.py`
  - Control Plane 보안: `M_API_001_anonymous.py`, `M_API_002_token_auth.py`, `M_API_003_bind_address.py` 등
  - 파일 시스템 보안: `M_FILE_001_config_permissions.py`, `M_FILE_002_certificate_permissions.py`
  - 총 18개의 체크 모듈 구현

- **동적 로드 메커니즘**: `pkgutil.iter_modules()`를 활용하여 `scanner/checks/` 디렉토리의 모든 체크 모듈을 자동으로 탐지하고 로드
  - 새로운 체크 추가 시 코드 수정 없이 자동 인식
  - 확장성과 유지보수성 향상

- **표준화된 결과 형식**: 모든 체크는 동일한 딕셔너리 구조로 결과 반환
  ```python
  {
    "CheckID": "CHK-M-API-001",
    "Result": "PASS/FAIL/ERROR",
    "ObjectType": "Pod/Container/Cluster",
    "ObjectName": "리소스 이름",
    "Namespace": "네임스페이스",
    "Reason": "검사 결과 설명",
    "Evidence": {"증거 데이터"},
    "Remediation": "해결 방법",
    "Severity": "Critical/High/Medium/Low"
  }
  ```

### 점수 기반 평가 시스템
- 각 체크 항목에 `points` 속성 부여 (최대 5-6점)
- PASS 시 점수 획득, FAIL/ERROR 시 0점
- 총점 대비 백분율로 보안 등급 산출 (Perfect/Good/Fair/Poor)

## 2. 동적 분석 및 정적 분석 적용

### 동적 분석 (Runtime Analysis)

#### Kubernetes API 기반 런타임 상태 조회
- **실행 중인 클러스터에 직접 접근**: Kubernetes Python Client를 통해 실제 실행 중인 클러스터의 리소스 상태를 실시간으로 조회
  - `kubernetes.client.CoreV1Api()`를 통한 Pod, Namespace 등 리소스 동적 조회
  - 클러스터 내부 실행 시 `load_incluster_config()`, 외부 실행 시 `load_kube_config()` 자동 선택
  - **동적 분석 근거**: `v1.list_pod_for_all_namespaces()`로 **실행 중인 모든 Pod**의 런타임 상태를 조회하여 `securityContext.privileged` 등 실제 적용된 설정 검사
  - 설정 파일이 아닌 **실제 배포된 리소스의 현재 상태**를 확인

#### kubectl 명령어 기반 실행 중인 파드 설정 분석
- **Control Plane 컴포넌트의 런타임 설정 검사**: `kubectl get pods -n kube-system -o json`을 통해 **실행 중인** API Server, Scheduler, Controller Manager 파드 정보 추출
- **커맨드 라인 인자 파싱**: 파드의 `command`와 `args` 필드에서 **실제 실행 중인** 보안 관련 플래그 추출
  - 예: `--anonymous-auth`, `--token-auth-file`, `--bind-address` 등
  - 플래그 값의 안전성 검증 (예: `--bind-address=0.0.0.0`은 FAIL, `127.0.0.1`은 PASS)
  - **동적 분석 근거**: 설정 파일이 아닌 **실제 실행 중인 파드의 런타임 인자**를 확인

#### 파드를 통한 파일 시스템 접근
- **kubectl exec를 통한 동적 파일 접근**: `kubectl exec <pod> -- ls -ld <file>` 명령으로 실행 중인 파드를 통해 컨트롤플레인 노드의 파일 권한 확인
  - `/etc/kubernetes/manifests/` 디렉토리의 매니페스트 파일 권한
  - 인증서 파일(`.crt`, `.key`)의 권한 (600 이하 권장)
  - **동적 분석 근거**: 파일을 직접 읽는 것이 아니라 **실행 중인 파드를 통해** 파일 시스템에 접근하여 현재 상태 확인

### 정적 분석 (Static Analysis)

#### 로컬 파일 시스템 직접 접근
- **파일 권한 검사**: 컨트롤플레인 노드에서 직접 실행 시 `os.stat()` 및 `stat` 모듈을 활용하여 Kubernetes 설정 파일의 권한 검증
  - 로컬 파일 시스템에서 직접 파일 메타데이터 확인
  - 정적 분석 근거: 파일 내용이나 설정을 직접 읽어 분석

### 병렬 처리 최적화
- **ThreadPoolExecutor**를 사용한 동시 실행 (기본 6개 워커 스레드)
- 각 체크를 독립적으로 실행하여 전체 스캔 시간 단축
- 체크 타입에 따라 적절한 파라미터 자동 전달 (`k8s_client` 또는 `kubeconfig`)

## 3. 결과 출력

### 다중 형식 지원
- **JSON 형식**: 구조화된 데이터로 프로그램적 처리 가능
  - `json.dumps()`를 사용하여 UTF-8 인코딩, 들여쓰기 적용
  - ScanID, Timestamp, Results 배열, Summary 포함

- **HTML 형식**: 시각적으로 보기 좋은 웹 리포트
  - 반응형 디자인, 색상 코딩 (FAIL: 빨강, PASS: 회색)
  - 요약 대시보드: 총점, 백분율, 등급, 통계
  - 상세 결과 테이블: 체크 이름, 대상 리소스, 결과, 점수
  - FAIL 항목에 대한 경고 메시지 및 해결 방법 표시

- **Markdown 형식**: 문서화 및 버전 관리에 적합
  - 표 형식의 결과 정리
  - FAIL/ERROR 항목에 대한 상세 설명 섹션
  - GitHub 등 플랫폼에서 바로 렌더링 가능

- **텍스트 형식**: 간단한 CLI 출력
  - 요약 정보 (총 체크 수, Passed/Failed/Error 수, 보안 점수, 등급)
  - 각 체크별 상세 결과 (CheckID, Result, Severity, Resource, Remediation)

### 자동 파일 저장
- 결과 디렉토리(`results/`) 자동 생성
- 파일명 형식: `{ScanID}_{Timestamp}.{extension}`
- JSON과 HTML 파일을 동시에 저장하여 다양한 용도로 활용 가능

### GUI 통합 출력
- PySimpleGUI 기반 실시간 진행 상황 표시
- 심각도별 카운터 (Critical, High, Medium, Low)
- 상세 결과 탭에서 각 항목 클릭 시 상세 정보 표시
- 결과 내보내기 기능 (JSON/CSV 형식)

### 점수 계산 및 등급 산정
- 각 체크의 `points` 속성을 기반으로 총점 계산
- 백분율에 따른 등급 자동 산정:
  - 100%: Perfect
  - 80% 이상: Good
  - 60% 이상: Fair
  - 60% 미만: Poor - Needs Improvement

## 4. 연구 결과

### 구현된 보안 체크 통계
- **총 체크 항목**: 18개 모듈
- **검사 카테고리**:
  - **Control Plane 보안**: 10개 (API Server 6개, Controller 2개, etcd 2개)
  - **Pod 보안**: 2개 (Privileged, Namespace Isolation)
  - **파일 시스템 보안**: 3개 (Config, Certificate, etcd Data)
  - **보안 패치**: 1개
  - **기타**: 2개

### 심각도별 분류
- **Critical**: 7개 체크 (각 6점, 총 42점)
  - API Server 익명 접근, 토큰 인증, TLS, Authorization, Audit
  - etcd 암호화, TLS
  - 인증서 파일 권한
- **High**: 11개 체크 (각 5-6점, 총 61점)
  - Pod privileged, Namespace isolation
  - API Server bind-address, Controller 인증/TLS
  - 설정 파일 권한, etcd 데이터 권한
  - 보안 패치 적용

### 성능 및 효율성
- **병렬 처리**: ThreadPoolExecutor를 통한 6개 워커 스레드 동시 실행
- **스캔 시간**: 평균 10-15초 (클러스터 규모에 따라 변동)
- **확장성**: 동적 로드 메커니즘으로 새로운 체크 추가 시 코드 수정 불필요
- **호환성**: Kubernetes 1.20+ 버전 지원

### 검사 범위 및 적용성
- **동적 분석 범위**:
  - 실행 중인 모든 Pod의 보안 컨텍스트 검사
  - Control Plane 컴포넌트의 런타임 설정 검증
  - 실제 배포된 리소스의 현재 상태 확인
- **정적 분석 범위**:
  - 컨트롤플레인 노드의 설정 파일 권한 검사
  - 인증서 및 키 파일의 접근 권한 검증
- **실제 적용 가능성**:
  - 로컬 개발 환경 (Minikube, Kind 등)
  - 자체 관리형 Kubernetes 클러스터
  - CI/CD 파이프라인 통합 가능

### 결과 출력 및 활용성
- **다중 형식 지원**: JSON, HTML, Markdown, 텍스트
- **시각화**: HTML 리포트의 대시보드 및 색상 코딩
- **자동화**: 결과 파일 자동 생성 및 저장
- **통합성**: GUI, CLI, API 모드 지원으로 다양한 사용 시나리오 대응

### 평가 시스템
- **점수 기반 평가**: 총 103점 만점 (18개 체크 × 평균 5.7점)
- **등급 산정**: Perfect/Good/Fair/Poor 4단계
- **상세 피드백**: 각 FAIL 항목에 대한 구체적인 해결 방법 제공
- **증거 수집**: 체크 결과에 Evidence 필드로 상세 정보 포함

### 주요 발견 사항 (예시)
- **Pod 보안**: privileged 모드 사용 컨테이너 탐지
- **Control Plane**: 익명 접근 허용, TLS 미설정 등 Critical 이슈 발견
- **파일 시스템**: 과도한 권한을 가진 설정 파일 탐지
- **네트워크**: 외부 접근 가능한 bind-address 설정 발견

### 실용성 및 기여도
- **사용자 친화적**: GUI 인터페이스로 비전문가도 쉽게 사용 가능
- **실시간 피드백**: 스캔 진행 상황 실시간 표시
- **해결 방법 제공**: 각 보안 이슈에 대한 구체적인 Remediation 가이드
- **표준 준수**: Kubernetes 보안 모범 사례 기반 검사 규칙
